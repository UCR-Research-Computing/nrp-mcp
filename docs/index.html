MCP server/Nautilus/v0.6.4

Run your research on Nautilus by talking to your AI assistant.

nrp-mcp is a small MCP server that runs on your own computer. Point it at your Nautilus sign-in and it turns "here is my code, run it on a GPU" into a reviewed plan and a running job. It knows the NRP's rules, so you don't have to learn Kubernetes first.

What it does

From "run this" to a running job

Each tool is named for what you want rather than for Kubernetes objects. Every result starts with a plain-language summary and, where useful, the kubectl equivalent so you learn as you go.

Runs locally, as you

It runs on your computer with your kubeconfig and the NRP's own sign-in. It never reads or stores your token, and nothing leaves your computer except the Kubernetes calls you approve.

Reviewed plans, two-step confirm

Planning creates nothing. You see the image, size, decisions and manifests first. Running and cleanup need a single-use token bound to the exact plan, valid for 10 minutes.

Knows the NRP rules

Non-sensitive data only, Jobs instead of sleep loops, limits within 20% of requests, quota-gated GPUs and more. A plan that breaks a rule is refused, with the reason and the fix.

Jobs, sweeps and Slurm scripts

"Run it 200 times with different seeds" becomes an Indexed Job. #SBATCH lines are translated, and a Slurm array script runs unchanged with its array variables set per task.

"Why did it fail?"

Plain-language diagnosis with a fix: out of memory, no free GPU, quota, image pull, crashes. Progress and logs with tail and grep.

Notebooks, data and web apps

Private Jupyter or VS Code sessions through port-forward, in-cluster dataset downloads to a shared volume, and lab tools on HTTPS, published only after you type the URL back.

Laptop setup on Linux, macOS, Windows

nrp-mcp setup installs kubectl and kubelogin into your user folder (SHA256-checked, no admin rights) and signs you in. CI installs and checks them on every change on all three systems.

Works with your MCP client

Tested end to end with Hermes Agent, Gemini CLI, OpenCode and Claude Code. Also works with Claude Desktop, VS Code, Cursor and any other MCP client.

The tools

Nine tools

Five are read-only. The rest change things only as listed: with a flag, a confirm token, or a second confirm.

ToolChanges things?What it does
nrp_setuponly with fix=trueLaptop readiness: kubectl (version vs the cluster), kubelogin, NRP config, sign-in; installs or updates them with your yes
nrp_statusnoIdentity, namespaces, GPU quotas, workloads and what they ask for, volumes, public URLs, warnings
nrp_plannoInspects a project and a goal (job, sweep, web, session, llm-batch, volume, pull), applies every rule, returns a summary, decisions, refusals, manifests and a confirm token
nrp_runyes, with a tokenRuns an approved plan; web plans also need public_ack; writes a run card to <project>/.nrp/runs/
nrp_watchnoProgress, logs (tail/grep), diagnosis with a fix, public URL check
nrp_cleanupyes, two stepsLists your runs, then deletes one after a second confirm
nrp_sessionnoReadiness, port-forward command and local link for a notebook or VS Code session
nrp_datauploads onlyList, upload small non-sensitive files, download results from a volume
nrp_buildnoSuggests a Dockerfile and an NRP GitLab CI (kaniko) file

Also served: resources nrp://policy, nrp://gpus, nrp://storage, nrp://llm, nrp://kb, and prompts first_run, port_slurm_script, parameter_sweep, my_job_failed, host_web_tool, teach_workshop.

How it works

One binary between your assistant and the cluster

Your AI client starts nrp-mcp serve and talks to it over stdio. Planning and rule checks are pure, tested code; only the kube step touches the cluster, using kubectl as you.

AI client Hermes Agent, Gemini CLI, OpenCode, Claude Code, ...
MCP over stdio
nrp-mcp serve on your computer
  1. inspectreads your project folder: language, GPU use, entry point, web app, Slurm script
  2. planbuilds manifests from facts + goal (pure, tested)
  3. ruleschecks every NRP policy (pure, tested)
  4. storeplans, hashed confirm tokens, audit log
  5. kuberuns kubectl as you (kubelogin handles the sign-in)
your approved calls
Nautilus (Kubernetes) Jobs, Deployments, volumes, Ingress in your namespace

Small projects are copied into the pod as a ConfigMap and their requirements installed at start. Bigger ones get an image built on NRP GitLab (nrp_build). The full design, every rule and the test record are in SPEC.md.

Safety

Nothing happens without a yes

From the README's safety section. See SECURITY.md for details and how to report a problem.

Runs as you, on your computer

Uses your kubeconfig and the NRP's sign-in. Never reads or stores your token.

Single-use confirm tokens

Run and cleanup need a token bound to the exact plan, valid for 10 minutes.

Nothing goes public by accident

A web plan publishes only when you type its exact URL back.

Shared namespaces are safe

Every object is labelled with its owner; cleanup sees only your runs unless a namespace admin asks for everyone's.

Caps

On pods and GPUs running at once, tasks per sweep, and hours per run.

Audit log

Every change is logged at ~/.local/state/nrp-mcp/audit.log.

NRP rules built in, each with a test and a link to its source

  • non-sensitive data only
  • Jobs instead of sleep loops
  • limits within 20% of requests
  • quota-gated GPUs (A100/H100/H200/GH200)
  • no GPUs on long-running services
  • allowed priority classes only
  • secrets kept out of specs
Quick start

Five steps

You need a Nautilus account and a namespace. Sign in at nrp.ai with your institution; students are added to a namespace by their PI, faculty can request one. UCR researchers: see Getting access.

  1. Install nrp-mcp

    Linux or macOS:

    curl -fsSL https://raw.githubusercontent.com/UCR-Research-Computing/nrp-mcp/main/scripts/install.sh | sh

    Windows: download nrp-mcp_<version>_windows_amd64.zip from Releases, unzip it and keep nrp-mcp.exe somewhere handy. With Go installed, this works everywhere:

    go install github.com/UCR-Research-Computing/nrp-mcp/cmd/nrp-mcp@latest

  2. Download your NRP config

    At nrp.ai/config (it lands in Downloads).

  3. Get your computer ready

    nrp-mcp setup

    setup checks everything first and asks before changing anything. Then it installs kubectl and the kubelogin sign-in plugin (official releases, SHA256-checked, into your user folder, no admin rights), puts the NRP config in ~/.kube/config (backing up an existing one), and signs you in through your browser. It ends with "This computer is ready for Nautilus."

  4. Add it to your AI client

    Tested end to end (live cluster, Gemini API key) with each of these:

    ClientAdd nrp
    Hermes Agenthermes mcp add nrp --command nrp-mcp --args serve
    Gemini CLIgemini mcp add nrp nrp-mcp serve
    OpenCodeadd "mcp": {"nrp": {"type": "local", "command": ["nrp-mcp", "serve"]}} to opencode.json
    Claude Codeclaude mcp add nrp -- nrp-mcp serve

    Claude Desktop, Cursor, VS Code and others (mcpServers block):

    {"mcpServers": {"nrp": {"command": "nrp-mcp", "args": ["serve"]}}}

    Use the full path to nrp-mcp if your client doesn't see your shell's PATH, and add "--namespace", "<your-namespace>" to args to pick a default.

  5. Ask

    "Where do I stand on Nautilus?"

Limits

  • Code is copied as text files under 200 KB each (900 KB total). Bigger projects need an image (nrp_build) or git.
  • nrp_build suggests files; it doesn't build. Builds run on NRP GitLab.
  • S3 uploads are guidance only; S3 keys come from the NRP portal.
  • Sessions are port-forwarded and never public. For zero install, the NRP runs a hosted JupyterHub.
  • The browser sign-in step of setup can't run in CI and is tested by hand.
